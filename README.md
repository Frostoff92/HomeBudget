# 🏠 HomeBudget

**HomeBudget** — учебно-практический проект на Go для учёта и анализа семейных расходов на основе чеков. Проект развивается поэтапно: Go Core и CSV Import → PostgreSQL → контейнеризация → GitLab CI/CD.

> **Статус:** в разработке (MVP). Базовое ядро Go и полный импорт CSV реализованы. Следующий этап — PostgreSQL. Репозиторий публичный; реальные финансовые данные хранятся локально.

## Задачи проекта

- Учёт расходов по чекам, магазинам, категориям и типам трат.
- Импорт записей из CSV, полученных из Excel.
- Детализация позиций чеков (*Items*) и связь с чеками по `Receipt ID`.
- Аналитика расходов по магазинам, категориям и периодам.
- Практика Go, PostgreSQL, Docker, автоматизированного тестирования и GitLab CI/CD.

## Что уже работает

- Модель `Purchase` и тип `ExpenseType`.
- Полный импорт CSV без искусственного ограничения количества записей.
- `parsePurchase()` — проверка числа полей, преобразование суммы и даты, создание и валидация покупки.
- `parseMoney()` — преобразование денежных строк с десятичной запятой в целые евроценты (`int64`) без `float64`, с проверками формата, отрицательных значений и переполнения.
- `isEmptyRecord()` — фильтрация записей, все поля которых пусты.
- Продолжение импорта при ошибке обработки отдельной записи после успешного чтения CSV.
- Раздельный учёт импортированных, отклонённых и пустых записей.
- Расчёт общей суммы и функция расчёта расходов по выбранному магазину.
- Сверка количества покупок и общей суммы с исходным Excel без расхождений.

## Архитектура импорта

```text
receipts.csv
    │
    ▼
encoding/csv (Read + ReadAll)
    │
    ▼
isEmptyRecord() ── empty ──► Empty records
    │ non-empty
    ▼
parsePurchase() ── error ──► Skipped purchases
    │
    ├── parseMoney()
    ├── time.Parse()
    └── Purchase.Validate()
    │ success
    ▼
[]Purchase → calculateTotal() → formatMoney()
    │
    ▼
Import summary
```

`main()` управляет импортом, а отдельные функции отвечают за парсинг, валидацию, фильтрацию и расчёты. На текущем этапе данные хранятся в памяти; постоянное хранение ещё не реализовано.

## Источники данных и формат CSV

- Локальный реестр чеков Excel (*Receipts*).
- Локальная детализация покупок и справочники (*Items*) — импорт планируется.
- `receipts.csv` — локальный экспорт реестра чеков.

CSV содержит заголовок и восемь полей в фиксированном порядке:

| Поле CSV | Поле Go | Тип Go |
|---|---|---|
| Receipt ID | ID | `string` |
| Date | Date | `time.Time` |
| Store | Store | `string` |
| Total EUR | AmountCents | `int64` |
| Group | Category | `string` |
| Expense Type | ExpenseType | `ExpenseType` |
| Source File | SourceFile | `string` |
| Notes | Notes | `string` |

Разделитель — `;`, рекомендуемая кодировка — UTF-8, формат даты — `YYYY-MM-DD`, валюта — EUR, десятичный разделитель суммы — запятая. `Source File` и `Notes` необязательны. Заголовок пропускается; проверка его содержимого пока не реализована.

### Конфиденциальность

Реальные чеки, таблицы Excel и CSV с финансовыми данными не публикуются. `receipts.csv` исключается из Git через `.gitignore`. Перед коммитом необходимо проверять состав изменений. Текущий диагностический вывод может содержать поля ошибочной записи, поэтому реальные логи не следует публиковать; безопасное логирование остаётся в плане развития.

## Локальный запуск

Требуется установленный Go (версия согласно `go.mod`). Создайте локальный файл `receipts.csv` в корневой директории проекта. Пример полностью синтетических данных:

```csv
Receipt ID;Date;Store;Total EUR;Group;Expense Type;Source File;Notes
TEST-001;2026-01-01;Demo Store;12,50;groceries;regular;;Demo purchase
TEST-002;2026-01-02;Demo Store;7,50;household;one_time;;Demo purchase
;;;;;;;
```

Из корневой директории проекта:

```bash
go run .
```

Ожидаемый вывод для приведённого примера:

```text
Total CSV records: 3
Imported purchases: 2
Skipped purchases: 0
Empty records: 1
Imported total: 20.00 EUR
```

Инвариант успешного чтения и обработки файла: `Total CSV records = Imported purchases + Skipped purchases + Empty records`.

## Тестирование

```bash
go test -v -count=1 ./...
go vet ./...
```

20 unit-тестов охватывают денежный парсинг, валидацию покупок, парсинг CSV-записи и фильтрацию пустых записей. Проверяются позитивные и негативные сценарии, включая неверную дату, сумму, количество полей и частично заполненную запись. Внешний CSV для этих тестов не требуется.
